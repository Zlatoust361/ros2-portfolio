# Валидаторы каталога курсов

Три инструмента, которые гейтят CI в исходном проекте (здесь — работают
на трёх демонстрационных курсах в `program/courses/`, не на реальном
каталоге):

- **`graph.py`** — валидирует каждый `course.yaml` по JSON Schema
  (`program/schema/course.schema.json`), проверяет, что все
  `prerequisites`/`supersedes` ссылаются на существующие курсы, что
  `prerequisites` активного курса не указывают на `deprecated`, и что
  граф пререквизитов ацикличен (DFS с раскраской вершин). Флаг
  `--mermaid` печатает диаграмму графа.
- **`lint_glossary.py`** — терминологический линтер: не даёт переводить
  термины, которые в проекте решено не переводить (например «Gazebo» не
  должно превращаться в «беседка» — реальная ошибка автоперевода, не
  придуманный пример). По умолчанию пропускает черновики (`draft`) —
  решение, что проверять в полную силу, а что рано проверять, зашито
  явно, не забыто.
- **`check_links.py`** — находит битые внутренние ссылки: пути в
  `course.yaml` (`labs[].path`, `materials[]`) и упоминания путей в
  обратных кавычках внутри markdown-файлов. Эвристика для markdown
  специально сделана нестрогой (отсекает команды/флаги/типы сообщений
  ROS2, не только реальные пути) — трейдофф между ложными
  срабатываниями и полнотой проверки, сделанный осознанно, описан в
  докстринге файла.

Все три — чистый Python, без внешних сервисов: `pip install pyyaml
jsonschema`, дальше работает локально и в CI одинаково.
